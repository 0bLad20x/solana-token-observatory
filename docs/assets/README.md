# Presentation Assets

Das Haupt-README verwendet genau drei Medien unter stabilen Pfaden:

| Datei | Inhalt |
|---|---|
| `observatory-universe.png` | gefülltes Token Universe / Bubble-Map |
| `system-dataflow.gif` | kurze animierte Aufnahme des Operational Flow |
| `analyst-search.png` | Analyst-Workspace mit repräsentativer Frage, Antwort und Evidence |

Die Dateien wurden nach ihrer ursprünglichen Placeholder-Anlage unter denselben stabilen Pfaden aktualisiert. Wenn sich UI oder Aussage später wesentlich ändern, können die Captures erneut **unter denselben Dateinamen ersetzt** werden; die Markdown-Verweise müssen dadurch nicht angepasst werden.

## Zweck der Medien

Jedes Asset soll eine konkrete Frage eines neuen Lesers beantworten:

- `observatory-universe.png` — **Wie sieht die aktive Population im Produkt aus?**
- `system-dataflow.gif` — **Welche Teile des Systems arbeiten zur Laufzeit sichtbar zusammen?**
- `analyst-search.png` — **Wie sieht eine evidenzgebundene Analyse im Produkt aus?**

Die Medien sind Erklärung und Produktbeleg, nicht Dekoration und nicht technische Authority.

## Capture-Empfehlungen

### `observatory-universe.png`

- gefüllten, gut lesbaren Universe-Zustand verwenden;
- unterschiedliche Bubble-Größen und Cluster sichtbar lassen;
- unnötige Browser-Chrome nach Möglichkeit wegschneiden;
- vorzugsweise mindestens etwa 1600 px Breite.

### `system-dataflow.gif`

- Operational Flow während realer Aktivität aufnehmen;
- Discovery, Search, Write und Lifecycle-Bewegung erkennbar machen;
- ungefähr 6–12 Sekunden reichen;
- Lesbarkeit vor hoher Framerate oder maximaler Auflösung priorisieren.

### `analyst-search.png`

- reale Current-Data- oder selected-token Analyse zeigen;
- Frage, Antwort und Evidence-Struktur sichtbar lassen;
- keine API Keys, Zugangsdaten oder andere Secrets aufnehmen.

## Refresh-Kriterium

Ein Asset sollte erneuert werden, wenn es eine aktuelle README-Aussage nicht mehr zuverlässig illustriert, zentrale UI-Strukturen sichtbar veraltet sind oder ein neuer Capture die erklärte Funktion deutlich besser verständlich macht.

Diese Dateien sind reine Presentation Assets. Sie sind keine Architektur-, Daten- oder Lifecycle-Authority.
